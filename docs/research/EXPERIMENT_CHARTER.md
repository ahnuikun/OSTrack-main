# 实验目标章程：CMC-KF 候选关联

状态：冻结 v1
适用项目：`OSTrack-main-cmc-kf-candidate`
变更规则：只有新的实验证据或用户明确调整目标时才能修改；每次修改必须在文末追加变更记录。

## 1. 唯一研究问题

在不重新训练 OSTrack、每帧只进行一次网络前向的条件下，验证以下串行模块能否提高 UAV 单目标跟踪的准确性与稳定性：

```text
相邻完整帧 CMC
→ 将上一目标状态传播到当前相机补偿坐标
→ KF 预测目标位置与尺度
→ OSTrack 响应图提取 Top-K 空间候选
→ 融合 CMC 可信度、KF 可信度和候选响应置信度进行关联
→ 选择当前目标并受控更新 KF
```

实验最终必须回答：

1. CMC 是否改善了 KF 在 UAV 相机运动下的一步预测？
2. OSTrack 的 Top-K 响应候选中是否经常存在被 Top-1 错过的正确目标？
3. KF 运动先验能否在不显著伤害清晰 Top-1 的前提下选回正确候选？
4. 完整闭环是否在同 checkpoint 下提高 AUC/Precision/Normalized Precision，并通过逐序列长尾安全检查？

## 2. 模块设计目标

- 直接借鉴已发表方法和官方代码中的成熟技术作为技术起点；当前先验证效果，但同时记录为兼容本框架所做的实质性变通及其创新潜力。
- CMC 负责相机运动传播；KF 负责目标动态预测；候选关联负责在视觉候选之间作选择。三者职责不得混写。
- 候选关联第一版采用 UOSTrack MBPP / SAMURAI 风格的响应分数与 KF 一致性加权。
- 相机运动与目标动态的串行建模参考 MATA。
- UOSTrack、SAMURAI、NeighborTrack、MATA 是参考基线而不是设计上限。与本框架不兼容的状态、坐标、候选或更新逻辑应合理改造，不能生搬硬套。
- 新的兼容性变通可以进入完整方法，但必须保持因果、单次 OSTrack 前向、推理侧和可独立消融，并说明它解决了哪一处不兼容。
- 所有实现保持推理侧、可关闭、可逐项消融，并保留 OSTrack 原始输出作为对照。

## 3. 明确非目标

以下内容不属于本项目，后续实验不得因局部失败而自动转向：

- EWMA 残余运动预测；
- 残余向量记忆、残余可靠性或残余尺度保护；
- 训练新网络、微调 OSTrack、增加时序 token 或学习式关联头；
- 第二次 OSTrack 前向、全局检测器或额外重检测网络；
- 没有机制证据和独立消融就把工程改动包装成创新；
- 在四个固定 UAV 主数据集和 LaSOT 泛化集之外，未经登记继续扩展数据集或进行大规模参数搜索。

## 4. 固定技术边界

- Backbone、box head、checkpoint 权重和训练配置保持不变。
- `TEST.SEARCH_SIZE=256` 等测试几何必须与 checkpoint 匹配。
- 每帧最多一次 OSTrack 前向；CMC、KF 和关联均为轻量后处理。
- CMC 使用相邻完整 RGB 帧的背景稀疏光流与鲁棒单应估计。
- KF 状态至少包含中心、尺度及其速度；状态先经相机运动传播，再执行目标动态预测。
- Top-K 候选来自同一响应图，候选框使用原 size/offset map 解码。
- 低可信观测允许输出，但不得无条件写入 KF；predict 与 update 必须分离。
- 所有影响输出的决策必须记录逐帧诊断字段。

## 4.1 允许且鼓励的兼容性创新

已有论文方法移植到本框架时，可以围绕以下接口作合理变通：

- 将 CMC 质量连续传播到 KF 协方差或关联权重，而不是只作二值开关；
- 在单应传播后统一变换 KF 状态、速度和协方差，使目标动态与相机运动真正解耦；
- 根据 OSTrack 响应峰的歧义程度校准运动先验强度，避免固定权重推翻清晰 Top-1；
- 将候选选择与 KF 观测写入分离，避免错误候选污染状态；
- 将 NeighborTrack 类短轨迹放到相机补偿后的坐标中进行关联，降低相机运动对轨迹距离的干扰；
- 设计其他仍满足本章程唯一数据流和技术边界的关联或状态控制方法。

每项变通必须登记 `source limitation → local adaptation → expected mechanism → ablation ID → evidence`。不能独立关闭、无法解释或无法消融的变通不得进入 full 版本。

## 5. 成功判据

完整版本只有同时满足以下条件才判定有效：

- 在匹配 checkpoint 的 DTB70、UAVDT、VisDrone、UAV123 四个 UAV 主数据集上完整评测，并与 E0 OSTrack 和 E1 CMC-only 比较；
- 至少一个主要收益能够由 rescue/harm、Top-K coverage 或 KF 预测误差等机制指标解释；
- 逐序列最差回归、负增益序列比例和 P95/P99 回归通过冻结 gate；
- 结果文件完整、无 NaN/Inf、可从 manifest 和 Git hash 复现；
- 运行时间开销被单独报告，且没有隐藏的第二次网络前向。

四个 UAV 主数据集的地位相同。执行顺序可按耗时从短到长安排，但不能把排序解释为数据集重要性或用前面数据集的结果取消后续主实验。LaSOT 只用于验证方法离开 UAV 专用场景后的泛化和通用性。

若 Top-K oracle coverage 本身不足，结论应是“候选生成限制了关联上限”，而不是继续堆叠运动模型。若 KF 重排救回率低于伤害率，结论应是当前关联无效，而不是回到残余运动路线。
